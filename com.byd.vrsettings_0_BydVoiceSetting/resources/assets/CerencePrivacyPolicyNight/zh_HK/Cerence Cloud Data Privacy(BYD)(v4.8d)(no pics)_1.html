引言

受眾、範圍及目的

 

Cerence 雲端服務（CCS）平台是 Cerence 的方案，涵蓋多租戶技術、基於雲端的語音辨識和資訊娛樂。CCS 平台透過利用 Cerence 的語音辨識、自然語言認知、文字預測和內容功能，將已連接的車輛蛻變成自然用戶體驗。CCS 能夠處理數量龐大的交易來提供所請求的服務。

 

本文件適用於計劃透過 Cerence 指定的第三方雲端服務供應商並在其中部署及使用 Cerence 雲端服務的 Cerence 車輛客戶。

本文件提供 CCS 方案的概覽，並且著重於方案當中的數據策略。數據策略提供已收集數據、生成數據、數據儲存方式以及圍繞數據處理的私隱/安全機制之全面綜覽。Cerence 發佈本白皮書的目標是以透明的方式提供數據流的整體綜覽，以便我們的客戶能夠實行其數據私隱政策，並遵從各項私隱法規，例如《歐盟通用數據保障條例》（GDPR）。

 

 

文件狀態

 

本文件已通過 Cerence 工程及產品管理部門審核。文件描述截至發佈日的 Cerence 雲端架構以及與數據私隱及安全相關的做法。本文件的更新將會不日發佈，以反映 Cerence 雲端服務（CCS）方案的更改，這些更改由新功能、技術創新、法律變更及其他因素所推動。

 

 

CCS 方案概覽

CCS 數據流概覽

 

CCS 平台直接或透過「客戶閘道」接收來自車用主機的終端用戶請求。請求在 Cerence 執行階段環境當中處理（在某些情况下是在與第三方內容供應商互動以獲取資訊娛樂內容時），然後將應答回傳給車用主機。

 

系統運作狀況資訊會傳送至 Cerence 全球營運中心（GOC），以確保服務品質並達到可用性目標。使用狀況度量指標會傳送至 Cerence 商業智能系統，以支援服務管理和會計功能。在處理過程中生成的若干元數據會傳送至 Cerence ResearchGrid，以便進行離線分析並持續改良核心技術。

 

當駕駛者執行車用主機上支援語音的應用程式時，本機嵌入式應用程式就會收集說出的指令（例如，「星期六在亞特蘭大的天氣會是怎樣？」），然後透過客戶閘道將該項輸入串流至 CCS 執行階段環境。語音指令的結果會回傳至車輛，而當中的 Cerence 嵌入式軟件裡的本機仲裁邏輯會決定給予駕駛者的最終結果應該源自嵌入式語音合成軟件或是來自 CCS 平台上的語音合成軟件。

 

 

車輛/閘道概覽

 

車用主機為車內與車外執行的應用程式創建用戶介面。當駕駛者啟動後，客戶應用程式就會收集來自音訊和其他感應器的輸入，以便在車輛的駕駛座艙中處理及提供應答。這些語音指令請求經由安全的 TLS 連結透過客戶閘道傳送至 CCS 平台進行即時處理。

 

在車用主機上執行的客戶應用程式的一項關鍵功能，是當連接到客戶閘道以傳遞語音處理請求時，這些客戶應用程式會建立及傳遞一個全域唯一識別碼（GUID）。建立 GUID 完全在客戶的控制範圍內，而每輛車的 GUID 都應是獨一無二。Cerence 明白 GUID 可與駕駛者解除關聯。它不應該是車輛識別號碼、電話號碼或任何其他形式的個人資料。從 CCS 的角度而言，這個由客戶建立的 GUID 是一個「外部 ID」。

 

在車用主機上執行的客戶應用程式的另一項關鍵功能，是能夠上載文字數據（語言模型登錄「LME」數據），以提升語音辨識效能。我們的構思是客戶應用程式可以從本機通訊錄上載聯絡人姓名。這些姓名用於即時以統計方式偏向辨識結果，從而提升辨識效能。

 

 

CCS 方案元件概覽

 

CCS 執行階段環境：CCS 執行階段環境處理即時終端用戶請求。它專為效能、可規模性和可用性而設計。CCS 執行階段環境包含 Cerence 服務閘道、Cerence 處理引擎及 Cerence 運作工具。

Cerence 服務閘道：在 CCS 執行階段環境當中，Cerence 服務閘道會管理傳入的終端用戶請求和工作階段。Cerence 服務閘道的一項關鍵功能，是將車用主機上的客戶應用程式（以及其他客戶應用程式）建立的「外部 ID」轉換成一個「內部 ID」。這項從外部 ID 到內部 ID 的轉換是透過在閘道內的工作階段開初完成的不可逆單向密碼雜湊函數而實現。將外部 ID 雜湊轉換成內部 ID，可確保終端用戶請求的任何處理都與用戶進一步解除關聯，而且該處理所建立的任何數據都不包含外部 ID。

 

Cerence 處理引擎：在 CCS 執行階段環境中，Cerence 處理引擎使用大型統計模型來套用大量轉換和演算法，以接受駕駛者所說出的指令，將其轉換成文字翻譯並解讀其意圖。若由客戶應用程式提供，則 LME 數據會用於偏向即時識別結果。此處理的結果是，處理引擎會建立出包含說出的話語和處理效能資訊的語音數據記錄。經雙方同意，LME 數據將不會被記錄。

 

Cerence 運作工具：在 CCS 執行階段環境當中，Cerence 運作工具從伺服器、網絡裝置等接收基礎架構記錄（例如系統記錄）。這些記錄不包含產生自終端用戶請求處理的語音話語數據或其他應用程式層面數據。

Cerence 全球營運中心：Cerence 全球營運中心（GOC）一年 365 天每天 24 小時無間斷監控 CCS 執行階段環境。來自 CCS 執行階段環境的效能指標、度量指標和系統運作狀況資訊會提交給 GOC 工程師，以確保高效能和高可用性水平。這些效能指標、度量指標和系統運作狀況資訊不包含產生自終端用戶請求處理的語音話語數據或其他應用程式層面數據。

 

Cerence 商業智能系統：Cerence 商業智能系統從 CCS 執行階段環境接收使用狀況度量指標，以支援服務管理和會計功能。這些數據不包含語音話語。BI 的輸出是彙總結果，包含所有終端用戶請求處理的專案層面度量指標。這種彙總結果的例子包括交易數量和指令類型細項。彙總結果乃專為各個 RTE 數據中心生成。

第三方內容供應商：CCS 與第三方內容供應商（例如 Vaisala、HERE 等）互動，以便為某些終端用戶請求獲取資訊娛樂內容。對這些第三方內容供應商的査詢不包含語音話語數據，並只包含目前的地理位置和來自終端用戶請求的最少所需資訊以滿足請求。例如，若果駕駛者問：「星期六在亞特蘭大的天氣會是怎樣？」，對天氣內容供應商的査詢會包含車輛目前所在的地理位置、亞特蘭大市、以及星期六這個日子，並以這些各項作為査詢參數。對第三方內容供應商的査詢不包含任何類型的用戶 ID，而且査詢的執行是透過加密通道（例如 HTTPS）與供應商來往。

 

Cerence 研究網格（CRG）：Cerence 研究網格從 CCS 執行階段環境接收語音數據記錄。這些數據由處理引擎建立，組成的記錄包括內部 ID、說出的話語、從而產生的轉譯、闡釋和處理效能資訊。語音數據記錄以用戶級別儲存在 Cerence 搜尋網格上，但不保留關於該位用戶的任何其他直接識別資訊。

 

CCS 記錄概覽

 

CCS 雲端元件將數據記錄至稱為 CLI 或雲端記錄基礎架構的中央元件 RTE，它將所有資訊合併到專為每個語音命令請求（交易）而設的統一記錄檔中。這些記錄會傳輸至 Cerence 研究網格，而這些記錄的一部分（例如，沒有聲音的話語）會傳輸至 BI 平台。

數據代碼混淆程序駐留在 CLI 中，作為記錄合併程序的一部分。以下與數據私隱相關的功能已套用：

·       地理位置粗略至只有一個小數位（預設），或完全從記錄中消除。

·       識別和闡釋結果乃按網域篩選

o       例如，SMS 短訊撰寫交易會將記錄中的音訊完全移除，並將任何識別和闡釋結果消除

 

部分篩選/消除規則為全球套用，部分則以應用程式特定或數據中心特定的形式套用。這些規則透過各個 Cerence 資料中心內保留的記錄篩選/消除配置檔案進行控制。當第三方或本機結果確定後並在回傳至車輛以完成處理之前，這些結果亦將包含在語音數據記錄中。客戶可以聯絡 Cerence，要求套用更嚴格的篩選和記錄消除規則。這些是唯一可用於疑難排解、研究和商業智能的記錄。

 

終端用戶同意 Cerence 雲端服務（CCS）：客戶負責從終端用戶收集其同意及/或向其提供適當的通知，以啟用 Cerence 雲端服務。倘若未完成同意或終端用戶撤回其同意，則特定車輛的 Cerence 雲端服務可能會被停用。當 CCS 停用時，所有語音助理服務皆會保留在車內，僅由 Cerence 的嵌入式軟件處理。當 CCS 已停用時，嵌入式語音記錄不會向 CCS 傳送。

選擇退出/選擇加入：Cerence API 允許應用程式將交易設置為「選擇加入」或「選擇退出」記錄。車內應用程式有責任收集該項資訊（例如透過 GUI）並將其傳遞至 CCS 交易。

帶有「選擇退出」旗標的交易會消除記錄中的所有資訊，僅數個關鍵欄位（例如應用程式 ID、時間標記和伺服器使用時間）除外。若 CCS 已停用，則由於 CCS 沒有收集任何數據，記錄的配置並無實際意義。

 

終端用戶同意產品改良：此外，嵌入式軟件為上游軟件提供將產品改良旗標設定為 FALSE 的能力，作為選擇退出產品改良的機制。在用戶級別將此旗標設定為 FALSE 會停止令語音數據記錄流向 CRG，防止日後從該用戶收集的語音數據被用於建立或訓練我們的下一代語音模型。因此，舉例而言，若果 GUI 開發人員為產品改良提供了特定的單獨同意，而終端用戶拒絕同意或撤回此同意，則開發人員應將此旗標設定為 FALSE 以完成選擇退出機制。

 

 

CCS 部署架構

執行階段環境

 

Cerence 目前在不同國家/地區設有 CCS 執行階段環境，以處理來自全球客戶主機的請求。在每個國家/地區，CCS 執行階段環境皆部署於公用雲環境中。執行階段環境包括：

·       北美洲

o       CCS 執行階段部署於位處美國維珍尼亞州的公用雲2。

o       當用戶將 VR 語言設定為美式英文、澳洲英文或新加坡英文時，NA 執行階段環境會用於處理來自美洲、亞洲（非中國）、大洋洲（包括澳洲和紐西蘭）的客戶流量。

 

·       歐洲

o       CCS 執行階段部署於位處荷蘭阿姆斯特丹的公用雲2。

o       歐洲執行階段環境用於處理來自歐洲、非洲和中東的客戶流量。

o       當用戶選擇源自歐盟的語言時，可以在其他任何地方使用。

 

·       中國

o       CCS 執行階段部署於位處中國張家口和上海的公用雲2。

o       中國執行階段環境用於處理所有源自中國大陸的客戶流量。

·       日本

o       CCS 執行階段部署於位處日本埼玉的公用雲2。

o       日本執行階段環境用於處理來自中國大陸以外的亞洲客戶流量，包括澳門和香港。

o       當用戶將 VR 語言設定為中文或廣東話時，可以在其他任何地方使用。

2注意：Cerence 可能會新增或更改這些位置，作為容量計劃和優化過程的一部分。Cerence 會就任何此類已計劃的更改（及其推出）通知客戶。

 

 

Cerence GOC

 

Cerence 全球營運中心（GOC）的角色是為 Cerence的全球雲端託管服務和營運提供 24 x 7 無間斷支援。

·       GOC 位於英國馬洛和印度浦那

·       馬洛 GOC 營運時間為上午 7 時至下午 7 時（世界協調時間英國時區）

·       浦那 GOC 營運時間為下午 7 時至上午 7 時（世界協調時間英國時區）

 

Cerence 研究網格

 

當數據從 Cerence 執行階段環境移出時，Cerence 研究網格（CRG）中的數據會從其執行階段形式分集出來。CRG 將這些語音數據維繫成一個大型的整體結構。

根據客戶的指示，語音通話記錄可被停止傳輸至 CRG，或者可以透過將內部 UID 欄位歸零以對語音數據記錄進行匿名化。

 

 

對於目前的絕大部分部署，已解除關聯的音訊檔案（又稱為「話語」）通常僅長數秒鐘，這進一步提高匿名程度。同樣地，這些話語通常是簡單直接的指令，其中不包含個人資料。透過解集數據，足夠龐大的數據池得以建立。此外，Cerence 亦進行了其自家研究，得出的結論是，在上述所有功能均已部署的情况下，要僅從語音識別出已知的數據主體是近乎不可能。

 

Cerence 研究網格從 CCS 執行階段環境接收語音數據記錄，然後將其用於 Cerence 研究人員所執行的各項改良。Cerence 研究全球研究識別碼資料庫（GRID）根據以下方式在全球各地處理記錄：

·       北美洲

o       北美洲網格建基於 Cerence 在美國麻省薩默維爾管理的數據中心。備份儲存於維珍尼亞州的 Azure US East 2 數據中心。

·       歐洲

o       目前，歐洲尚未有研究網格。所有執行階段記錄在傳送到北美洲的網格位置之前皆儲存於歐洲的執行階段環境中。

·       中國

o       目前，中國尚未有研究網格。所有執行階段記錄皆儲存於中國執行階段環境中，以遵從當地法規。記錄在傳送到北美洲的網格位置之前已進行匿名化。

·       日本

o       目前，日本尚未有研究網格。所有執行階段記錄在傳送到北美洲的網格位置之前皆儲存於日本執行階段環境中。

 

 

Cerence 商業智能系統

 

Cerence 商業智能系統從 CCS 執行階段環境接收應用程式記錄數據，以支援服務管理和會計功能。此數據不包含語音話語，只包含處理終端用戶請求時所產生的應用程式層面度量指標（例如歐盟數據中心的客戶交易數量）。

商業智慧系統目前託管於 Azure US East 2 中。

 

 

詳細節點架構

CCS 執行階段環境存取控制

Cerence 執行階段環境可由 Cerence 託管的站點可靠性工程工程團隊和

通話記錄處理：

 

通話記錄儲存系統作為 CCS 執行階段環境的一部分，合併來自多個 CCS 元件的通話記錄。每次元件處理全域交易的一部分時，都會建立一個通話記錄片段，並將其傳送到通話記錄儲存系統（在交易完成後立即進行）。通話記錄儲存系統會定期重組通話記錄片段來組成合併通話記錄。在合併過程中，通話記錄會修改以遵從客戶安全政策（例如不儲存音訊，不儲存訊息網域的 ASR/NLU 結果）。通話記錄合併後，就可供 GRID 後端和 BI 系統進行處理。每個系統都會定期單獨提取合併記錄中允許提取的部分。

 

商業智能（BI）

 

Cerence 商業智能系統從 CCS 執行階段環境接收應用程式記錄數據，以支援服務管理和會計功能。這些數據不包含語音話語數據，僅包含產生自處理終端用戶請求的應用程式層面度量指標（例如歐盟數據中心的客戶交易數量）。傳送到 BI 的唯一一項個人資料是 ASR 結果（用於追蹤客戶報告首 10 個使用狀況統計數據）、內部 ID（用於追蹤唯一用戶和整體流量使用狀况）和 NLU 網域（用於追蹤用戶報告的使用狀況類型）

 

所有執行階段環境都與 Azure US East 2 區域中的同一個中央 BI 系統整合。商業智能系統託管於 Azure US East 2 區域中。資料會傳送到 BI 系統以供用於以下目的：

 

·       推動客戶進行報告，報告可用於監控、分析、遵守 SLA、計費、瞭解使用狀况和客戶劃分與傾向等。

·       Cerence 可以使用生成的報告進行計費、產品改良、監控延遲/SLA/容量分析、預測等。

·       較長期儲存的已摘要數據可用於機器學習/AI 活動，以獲得更多見解，並為終端用戶提供更佳體驗。

 

BI 數據流

 

來自各種執行階段環境（例如美國、歐洲等）的數據從 CLI 中擷取出來，並轉換成適合摘要及報告的模型，然後傳輸到 位於 Azure 美國東部地區的中央數據倉庫，然後載入 OLAP 數據立方中。接著，報告和分析數據會從這些 OLAP 立方匯出，並可供選擇透過安全的（SSL）入門網站存取。

 

存取控制

 

BI 系統有三種存取類型：

 

1.       外部客戶（亦即客戶）透過 BI 入口（可選）

 

BI 入口設置為允許客戶僅查看特定於其部署的彙總報告。在存取 BI 入口和存取報告前，每位用戶（CCS 客戶）必須已獲明確供給配置。

 

2.       內部（Cerence）客戶透過 BI 入口或入口報告

 

BI 入口亦設置為允許內部 Cerence 用戶僅只生成彙總報告，以獲取見解及達到上述其他目的。彙總報告可生成為特定於某位客戶 / 某個客戶專案或跨客戶 / 跨客戶專案。

 

3.       開發人員 / 管理員

 

 

開發人員和管理員是 Cerence 的員工 / 承包商，他們需要存取 BI 系統以便對其進行開發和維護。這些員工/承包商在存取 BI 系統之前已獲提供特定權限。BI 系統的存取權僅基於需要知悉的情況下

 

 

全球營運中心（GOC）

 

GOC 的角色是為 Cerence的全球雲端託管服務和營運提供 24 x 7 無間斷支援。為此，中心每天 24 小時，每星期 7 天，每年 365 天都有工作人員當值，由訓練有素的人員負責確保服務正常運作並遵從已制訂的服務水平協議。所有負責執行 Cerence 的事件、事故、問題及更改管理流程的事故經理都經過 ITIL v3 Foundation 認證。所有 GOC 工程師都經過 RHCSA/RHCE 培訓，為 Cerence 的產品和服務提供一線及二線支援。

GOC 對 Cerence 的託管基礎架構、網絡和應用程式進行積極監控，並且是報告問題和事件的主要客戶聯絡中心。事件會導致 GOC 票單建立，以便記錄事件的影響、開始時間及解決時間，以及所有關聯的事故應對及還原服務的動作。中心執行各種工作，包括協調影響服務的事故/事件/警示的事件應對橋樑，就事件狀態通知客戶，以及協調第1 級及第 2 級應對直到完成解決問題。GOC 會定期追蹤效能 KPI 並報告服務效能。中心推動內部問題管理流程，以消除重覆發生並影響服務的事故，同時推動持續改良服務質素和正常運作。GOC 亦協調所有為執行 Cerence 託管基礎架構和服務的升級與維護所必需的更改，以確保與指定的維護間隔保持一致，並且是安全事故及事件管理（SIEM）程序偵測到的任何安全相關事故的協調中心點。GOC 亦控制對 Cerence 託管網絡和基礎架構的用戶存取，在必要時授予最小權限的存取，並遵從 Cerence 的全球安全政策。

 

GOC 員工目前身處於英國馬洛和印度浦那。他們擁有存取權限，並且能夠監控和介入，以解決所有國家/地區影響服務的問題。倘若需要更深入的疑難排解以解決問題，GOC 工作人員亦可透過值班傳呼機輪換制度來接洽更多名二線和三線支援工程師。當值員工遍佈世界各地，包括歐洲、美洲和亞洲。

 

GOC 地點透過雙 ISP 網絡連線連接到 Cerence 的全球網絡，確保維持服務和營運所需的連接能力。

GOC 所使用的數據不包含個人資料。數種類別的數據會流向 GOC 以監控和維持營運狀況。這些包括基礎架構記錄、度量指標數據、合成交易數據以及監控數據。這些數據集裡不允許任何個人資料。

·       基礎架構記錄由系統記錄、容器記錄和應用程式記錄組成。這些記錄提供與託管應用程式的實體和虛擬資產相關的資訊。

·       度量指標數據由網絡數據（傳送/接收、錯誤率）、磁碟數據（使用狀况、讀/寫速度、

錯誤、延遲）、CPU 數據（使用狀况）、記憶體數據（使用狀況）。

·       合成交易數據使用測試輸入模擬用戶交易，以驗證成功的交易處理。

·       監控數據從記錄、度量指標和合成交易數據彙總和構成相互關係，並以警示或事件以及顯示度量指標的概覽視圖形式提交給 GOC。

 

GOC 有權存取已彙總的 BI 資訊（非個人資訊），惟無法存取 Cerence 研究網格上的數據。

Cerence 執行階段環境 / Cerence 全球營運中心

 

執行階段環境中的數據讓 Cerence 工程師能夠根據客戶報告診斷系統問題，並進行定期內部分析。

 

 

Cerence 商業智能系統

 

商業智慧系統中的數據用於：

 

·       推動客戶（客戶）進行報告，報告可用於監控、分析、遵守 SLA、計費、瞭解使用狀况和客戶劃分與傾向等。

·       產生可供 Cerence 使用的報告，以便進行計費、產品改良、監控延遲/SLA/容量分析、預測等。

·       透過利用較長期儲存的數據進行機器學習/AI 建模，獲得更深入的見解，並為終端用戶提供更佳體驗。

Cerence 搜尋網格

 

Cerence 搜尋網格：Cerence 搜尋網格可從 CCS 執行階段環境接收語音數據記錄。這些資料由處理引擎建立，組成的記錄包括已假名化的內部 ID、說出的話語、從而產生的音訊文字轉譯、用戶請求的闡釋（意圖）和若干處理效能資訊。這項語音數據記錄視為「已解除關聯的數據」，是因為它儲存在 Cerence 研究網格上，而且我們知道數據僅來自單一用戶，惟不知曉關於該用戶的任何直接識別資訊。

 

聲學 / 語言 / NLU 模型更新：聲學模型對聲音在字詞中的表示方式進行編碼，例如「cat」中的「a」聽起來如何。語言模型對字詞如何組合成有意義的短語進行編碼。使用這兩種類型的模型，以及字典和其他輸入，語音辨識軟件就會輸出說話的最可能順序。

在 Cerence 研究網格中，原始語音數據經過彙總，並用於建構統計聲學、語言和 NLU 模型，這些模型為執行階段環境中的 Cerence 處理引擎提供動力。該等模型經過數以千計小時的語音和數以億計的文字數據（來自真實用戶描述真實事情的轉譯音訊）訓練。

 

獨立於說話者的語言模型適應：在 Cerence 研究網格中，獨立於說話者的語言模型適應（SI-LMA）過程能夠改善對市場特定和新流行術語的識別。這亦用於修正若干錯誤或識別錯誤。

 

說話者相關的聲學模型適應：在 Cerence 研究網格中，來自終端用戶話語的音訊會用於建構聲學模型適應，以優化經常使用系統的用戶之統計資料和識別。這種優化過程稱為說話者相關聲學模型適應（SD-AMA）。

 

 

 

Cerence 使用深度學習技術進行統計聲學、語言和 NLU 建模。該項技術由數據驅動，可透過使用更多數據來製作更優秀的模型。在我們的研究和工廠模型訓練過程中匯集所有客戶的數據，可以比起將客戶數據用於客戶特定模型達到更高準確度。

透過使用用戶自己的數據進行說話者相關適應，所有用戶皆可享受進一步的準確度提升。此外，每個應用程式在表達用戶意圖的方式上往往存在差異（例如出於畫面教學、廣告、手册、所有者人口統計資料、對以往語音系統的熟悉程度等原因），並具有不同的聲學條件分佈。透過獨立於說話者的適應和建模，將客戶數據用於客戶特定的應用場景進行改良，對於客戶駕駛者而言亦是獨一無二。

 

 

數據存取

 

儲存在 Cerence 研究網格中的數據獲企業層級管理的群組權限保護。對該資料的存取僅限於有需要的情況，並以最少權限的模式提供。換而言之，只有必須使用特定數據來建立或改良相關產品的研究人員方獲允許存取該數據。只有在已確認研究人員已獲取所有最新及必需的數據私隱和安全培訓後，方可根據經理的要求授予該等存取權。獲得授權後，只有獲批准的個人方可透過二次驗證獲得存取。每當研究人員的工作有所變動時，存取權限都會更新或被撤銷，通常每兩年進行一次審核。研究人員必須每年參與一次數據私隱及安全課程。

 

Cerence 研究小組擁有特定語言的語言學專家，以及獨立於語言的通用系統專家和深度學習專家。這些專家攜手合作，為我們的客戶提供最優秀的方案和服務。

作為全球組織及市場領導者，我們在世界各地招聘最優秀的系統專家和深度學習專家，並非完全集中於某個地方。所有這些專家的協同合作加快疑難排解的速度，並提升我們滿足 SLA 要求的能力。

 

 

Cerence 數據保留

 

Cerence 執行階段環境 / Cerence 全球營運中心

 

Cerence 執行階段環境內的語音數據記錄會保留最多 28 天，以支援除錯和疑難排解活動。這些語音數據記錄會傳送到研究網格，以支援聲學、語言和 NLU 建模活動，並且確實包含來自處理終端用戶請求的語音話語數據。語音數據記錄會在第 28 天從 Cerence 執行階段環境中被標示為逾時並被删除。

 

客戶應用程式提供並在 Cerence 執行階段環境中保留的語言模型登錄（LME）數據會在用戶閒置 6 個月後被清除。

Cerence 執行階段環境中的基礎架構記錄會根據審計目的所需而保留 90 天或更長時間。這些記錄不包含語音話語數據或來自處理終端用戶請求的其他應用程式層面數據。

 

 

 

Cerence 商業智能系統

 

從 CCS 執行階段環境傳送到 Cerence 商業智能系統的使用狀況數據會保留 6 至 7 個月，以確保可以無間斷製作兩個季度份量的彙總報告。商業智能系統製作的彙總數據報告將會保留 13 個月，惟亦會備份 / 封存額外 2 年。

 

 

Cerence 搜尋網格

 

Cerence 亦持續部署 3 年的保留期，這項數據保留標準透過在數據的有用生命週期結束時將其移除來進一步保護數據。Cerence 堅持政策、控制和對客戶的承諾，即使未來的技術允許，亦不會「重新關聯」已解除關聯的音訊數據。Cerence 謹記其作為數據處理者的義務，並確保不會將數據用於其收集目的以外的任何用途。

 

CRG 上的終端用戶數據（音訊和記錄）由一個中央集權的數據團隊管理，位於稱為「儲存庫」的目錄和檔案系統合集中。儲存庫數據通常儲存於大型 .zip 檔案中，這些 zip 檔案的索引保留在數據庫中。儲存庫檔案的備份由數據團隊進行。該些 .zip 檔案作為物件封存在容器中。研究人員禁止從儲存庫檔案複製音訊及/或記錄，因此數據集通常只是指向儲存庫資料的指標合集。這令數據團隊能夠滿足删除個別用戶（透過「內部 ID」辨識）數據及/或個人應用程式數據的請求。删除會對儲存庫及儲存庫檔案的備份生效。

 

在某些情况下，來自許多用戶的數據會組合在一起，並未連結到任何特定的說話者話語。由於就連與該數據相關聯的「內部 ID」亦已被排除，因此已彙總數據會匿名得更加徹底。它可能包括：

 

•                      從音訊檔案衍生的特徵向量。

•                      在識別資訊（如電話號碼）被混淆後來自許多用戶的文字組合。

•                      多個用戶共有的已註釋意圖。

 

保留彙總數據容許 Cerence 建立和支援語音模型。對於聲學模型訓練而言，可能依然需要「儲存庫」中的原始語音數據，惟不會製作副本，而存取永遠透過儲存庫進行。CRG 上的用戶數據僅可透過終端機、遠端桌面或存取研究人員的手提電腦/工作站的瀏覽器從研究網格存取。與 CRG 的連線永遠在 Cerence 的 VPN 內進行。將數據副本傳送到研究人員的手提電腦/工作站的行為受到限制。

 

 

縮短數據保留期的影響

 

我們的深度學習工廠模型訓練、適應過程和說話者相關的適應過程可有效利用 3 年份量的數據。將保留期縮短到少於 3 年會限制探索現場數據的準確度改善潛力。由於與其他應用程式相比，來自指定應用程式的訓練數據會過多提高該應用程式的效能，因此工廠模型可能對於客戶應用程式而言尤其不理想。

此外，可供用於針對客戶駕駛者進行適應的說話者相關數據會變得相當少量。若果長時間不使用系統，部分駕駛者甚至可能會感受到效能下降。最後，轉譯和註釋數據需要耗費極長處理時間和極高成本，方可供研究人員進行實驗並協助改善長遠基線效能。較長的 12 年保留期會維持，以支持這些數據。這個特殊的數據集佔已收集的所有客戶資料的極少部分（少於 1%）。

 

 

數據私隱管理

私隱管理

 

Cerence 建立了一個由數據擁有者和法律部門管理的私隱計劃，並由其商業部門當中的管理矩陣架構支援。Cerence 在關於資料的使用和保護方面致力對客戶保持開放和透明。為此，Cerence 制訂出一項網上私隱政策，並實施最長 3 年的保留期，即使對於已假名化的個人資料亦然。Cerence 亦實施管理數據保護和安全措施，例如關於由員工進行的標準數據存取和使用實踐、實體存取控制、二次驗證和存取要求、審計軌跡、記錄和監控的政策和程序。涵蓋資訊保護和數據安全的全球員工培訓為每年提供，並在有需要時輔以臨時培訓和溝通。
