Programa de Melhoria da Experiência do Usuário

 

Introdução

Público, escopo e objetivo

Este documento destina-se aos clientes automotivos da Cerence que pretendem implantar e usar os serviços Cerence Cloud em e por meio de provedores de serviços em nuvem terceirizados designados pela Cerence e concordam em transferir os registros de dados de fala do Ambiente de Execução CCS para o Cerence Research Grid (CRG).

 

O presente documento apresenta uma visão geral da solução CCS com foco no Programa de Melhoria da Experiência do Usuário no âmbito da solução. A Estratégia de Dados proporciona uma visão completa dos dados que são enviados, como são armazenados e os mecanismos de privacidade/segurança que envolvem o processamento de dados no CRG. O objetivo da Cerence com este informativo técnico é fornecer uma visão holística do fluxo de dados para que os motoristas e passageiros de veículos entendam como seus dados pessoais estão sendo usados.

Visão geral do plano de melhoria do produto

Visão geral do fluxo de dados

A plataforma CCS recebe solicitações do usuário final diretamente das unidades centrais dos veículos. A solicitação é processada no Ambiente de Execução Cerence (em alguns casos, durante a interação com Provedores de Conteúdo Terceirizados para recuperar o conteúdo de infoentretenimento) e uma resposta é enviada à Unidade Central do Veículo.

Determinados metadados gerados durante o processamento são transmitidos ao Cerence Research Grid para análise off-line e melhoria contínua da tecnologia principal.

 

Perguntas frequentes sobre o Programa de Melhoria da Experiência do Usuário

 

1: Quais são as situações em que os dados serão transferidos para o Cerence Research Grid (CRG)?

 

Quando um motorista ou passageiro de um veículo aciona um aplicativo com capacidade de reconhecimento de voz na Unidade Central do Veículo, o aplicativo coletará um comando de voz (por exemplo, “Fechar janela” ou “Como estará o tempo em Atlanta no sábado?”) e transmitirá esse comando para o Ambiente de Execução CCS. Caso o usuário final tenha consentido com o uso dos comandos e respostas por voz (“transações por voz”), os dados são elegíveis para serem transferidos para o CRG. Em geral, somente uma vez em um período de 24 horas (diariamente) todas as transações de voz elegíveis serão transferidas para o Cerence Research Grid (CRG).

 

 

2: Onde fica o Cerence Research Grid (CRG)?

 

O Cerence Research Grid (CRG) está localizado em um data center (centro de processamento de dados) gerenciado pela Cerence em Somerville, Massachusetts, Estados Unidos. Os backups são armazenados em um data center do US East 2 do Azure na Virgínia. A Cerence também usa o MS Azure para disponibilizar recursos adicionais de processamento para o data center gerenciado pela Cerence.

 

NOTA: A Cerence se reserva o direito de alterar os locais como parte dos processos de planejamento e otimização da capacidade. A Cerence informará os clientes (que iniciaram o processo) sobre quaisquer alterações planejadas.

 

 

3: Como os dados de voz são usados pelo Cerence Research Grid (CRG)?

 

No Cerence Research Grid, os dados brutos de voz são agregados e usados para criar modelos acústicos estatísticos, de linguagem e NLU que alimentam os mecanismos de processamento no Ambiente de Execução CCS. Esses dados são treinados com base em milhares de horas de fala - das quais apenas uma fração tem origem em veículos - e bilhões de palavras de dados de texto (áudio transcrito de forma prévia e contínua).

 

Além disso, os pesquisadores podem usar os dados para fazer análises de erros em chamadas que falharam (solução de problemas sistêmicos).

 

 

4: Que métodos se aplicam ao processamento de dados antes da transferência para o Cerence Research Grid (CRG)?

 

Os componentes de nuvem do CCS registram dados em um componente central chamado Cloud Logging Infrastructure (CLI), que combina todas as informações em um arquivo de registro unificado para cada transação. Esses registros são transferidos diariamente para o Cerence Research Grid.

6: Com que frequência os registros de chamadas de voz serão transferidos para o Cerence Research Grid (CRG)?

 

O sistema de armazenamento da infraestrutura de armazenamento de registro de chamadas (CLI), que faz parte do ambiente de execução do CCS, combina os registros de chamadas de vários componentes do CCS.

Cada vez que um componente processa parte de uma transação global, uma parte do registro de chamadas é criada e enviada para a CLI assim que a transação é concluída.

A CLI reagrupa as partes do registro de chamadas para formar um registro de chamadas mesclado, de modo que possa incluir o comando de voz e os elementos de resposta. Durante o processo de mesclagem, os registros de chamadas são modificados para atender às políticas de segurança do cliente (por exemplo, não manter arquivos de áudio e resultados de ASR/NLU no domínio de mensagens).

 

Quando um registro de chamadas é mesclado, ele fica disponível para processamento pelo back-end do GRID. Os pulls do back-end para o GRID são realizados diariamente (uma vez por dia).

 

7: Durante quanto tempo os dados são armazenados no Cerence Research Grid (CRG)?

 

A Cerence adotou um padrão de retenção de 3 anos de forma contínua e esse padrão de retenção de dados protege os dados ainda mais, eliminando-os no final de seu ciclo de vida útil. A Cerence mantém políticas, controles e compromissos com os clientes de não “reassociar” dados de áudio, mesmo que uma tecnologia futura permita fazê-lo. A Cerence está ciente de suas obrigações como processadora de dados e garante não fazer uso dos dados para outros fins que não aqueles para os quais foram coletados.

 

Os dados do usuário final (áudio e registros) no CRG são gerenciados por uma Equipe de Dados centralizada, em um conjunto de diretórios e sistemas de arquivos chamado “vault” (cofre). Os dados do cofre são normalmente armazenados em grandes arquivos .zip e os índices desses arquivos zip são armazenados em bancos de dados. Os backups dos arquivos do cofre são realizados pela Equipe de Dados. Os arquivos .zip são arquivados como objetos em contêineres. Os pesquisadores são proibidos de fazer cópias de áudio e/ou dos registros de arquivos do cofre, portanto, os conjuntos de dados geralmente são apenas coleções de ponteiros para dados no cofre. Esse procedimento permite que a Equipe de Dados atenda às solicitações de exclusão de dados de usuários individuais (identificados por meio do “ID interno”) e/ou de aplicativos individuais. As exclusões são aplicadas ao cofre e aos backups dos arquivos do cofre.
