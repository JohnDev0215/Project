Programa de melhoria da experiência do utilizador

 

Introdução

Público, âmbito e objetivo

Este documento destina-se aos clientes do sector automóvel da Cerence que planeiam implantar e utilizar os serviços Cerence Cloud em e através de fornecedores de serviços em nuvem terceirizados designados pela Cerence e que concordam em transferir registos de dados de fala do Ambiente de tempo de execução CCS para a Rede de Pesquisa Cerence (CRG).

 

Este documento apresenta uma visão geral da solução CCS, com destaque para o Programa de Melhoria da Experiência do Utilizador no contexto da solução. A estratégia de dados fornece uma visão abrangente dos dados enviados, da forma como os dados são armazenados e dos mecanismos de privacidade/segurança que envolvem o processamento de dados no CRG. Com este documento, a Cerence tem como objetivo fornecer uma visão holística do fluxo de dados, para que os condutores e passageiros dos veículos compreendam como os seus dados pessoais estão a ser utilizados.

Visão geral do plano de melhoria do produto

Visão geral do fluxo de dados

A plataforma CCS recebe os pedidos dos utilizadores finais diretamente das unidades centrais dos veículos. O pedido é processado dentro do ambiente de tempo de execução Cerence (em alguns casos, durante a interação com fornecedores de conteúdos de terceiros para obter conteúdos de informação e lazer) e é devolvida uma resposta à unidade central do veículo.

Alguns metadados gerados durante o processamento são enviados à rede de pesquisa Cerence para análise on-line e melhoria contínua da tecnologia principal.

 

FAQ para o Programa de Aperfeiçoamento da Experiência do Usuário

 

1: Em que situações serão os dados transferidos para a Rede de Pesquisa Cerence (CRG)?

 

Quando um condutor ou passageiro de um veículo invoca uma aplicação de voz na unidade central do veículo, a aplicação recolhe um comando oral (por exemplo, "fechar janela" ou "como estará o tempo em Atlanta no sábado?") e transmite esse comando ao ambiente de tempo de execução CCS. Se o utilizador final tiver consentido na utilização dos seus comandos e respostas vocais ("transacções vocais"), então os dados estarão elegíveis para serem transferidos para o CRG. Em geral, apenas uma vez num período de 24 horas (diariamente) todas as transacções de voz elegíveis serão transferidas para a rede de pesquisa Cerence (CRG).

 

 

2: Onde fica a Rede de Pesquisa Cerence (CRG)?

 

A rede de pesquisa Cerence (CRG) é baseada em um centro de dados gerenciado pela Cerence, localizado em Somerville, MA, EUA. As cópias de segurança são armazenadas num centro de dados Azure US East 2 na Virgínia. A Cerence também utiliza o MS Azure para fornecer capacidades de processamento adicionais para o centro de dados gerido por ela mesma.

 

NOTA: A Cerence pode alterar estas localizações como parte dos processos de planeamento e otimização da capacidade. A Cerence informará os clientes (que tenham efetuado o lançamento) de quaisquer alterações previstas.

 

 

3: Como é que os dados de voz são utilizados pela rede de pesquisa Cerence (CRG)?

 

Dentro da rede de pesquisa Cerence, os dados brutos da fala são agregados e utilizados para construir modelos estatísticos acústicos, linguísticos e NLU que alimentam os motores de processamento no ambiente de tempo de execução CCS. Esses dados são treinados com base em milhares de horas de discurso - apenas uma fração das quais provém de veículos - e milhares de milhões de palavras de dados de texto (áudio prévia e continuamente transcrito).

 

Além disso, os pesquisadores podem utilizar os dados para realizar análises de erros em chamadas falhadas (resolução de problemas sistémicos).

 

 

4: Que métodos se aplicam ao tratamento de dados antes da transferência para a Rede de Pesquisa Cerence (CRG)?

 

Os componentes da nuvem CCS registam os dados num componente central denominado Infra-Estrutura de Registo na Nuvem (CLI), que reúne todas as informações num ficheiro de registo unificado para cada transação. Estes registos são transferidos diariamente para a Rede de Pesquisa Cerence.

6: Com que frequência serão transferidos os registos das chamadas de voz para a Rede de Pesquisa Cerence (CRG)?

 

O sistema de armazenamento da infraestrutura de armazenamento de registo de chamadas (CLI) que faz parte do ambiente de tempo de execução CCS funde os registos de chamadas de vários componentes CCS.

Sempre que um componente processa parte de uma transação global, é criada uma parte do registo de chamadas que é enviada para o CLI imediatamente após a conclusão dessa transação.

A CLI volta a juntar as partes do registo de chamadas para formar um registo de chamadas fundido, de modo a poder incluir tanto o comando de voz como os elementos de resposta. Durante o processo de fusão, os registos de chamadas são modificados para cumprir as políticas de segurança do cliente (por exemplo, não manter o áudio e os resultados ASR/NLU para o domínio de mensagens).

 

Quando um registo de chamadas tiver sido fundido, fica disponível para processamento pela REDE backend. Os extratos de backend para a REDE são efetuados diariamente (uma vez por dia).

 

7: Por quanto tempo são os dados armazenados na Rede de Pesquisa Cerence (CRG)?

 

A Cerence implementou a retenção de 3 anos numa base contínua e esta norma de retenção de dados protege ainda mais os dados, removendo-os no final do seu ciclo de vida útil. A Cerence mantém políticas, controlos e compromissos com os clientes para não "re-associar" dados de áudio, mesmo que a tecnologia futura o permita. A Cerence está consciente das suas obrigações enquanto processadora de dados e garante que não utiliza os dados para outros fins que não aqueles para os quais foram recolhidos.

 

Os dados do utilizador final (áudio e registos) na CRG são geridos por uma equipa de dados centralizada, num conjunto de directórios e sistemas de ficheiros denominado "cofre". Os dados do cofre são normalmente armazenados em grandes ficheiros .zip e os índices destes ficheiros zip são mantidos em bases de dados. As cópias de segurança dos ficheiros da caixa-forte são feitas pela equipa de dados. Os ficheiros .zip são arquivados como objetos em contentores. É proibido aos pesquisadores fazer cópias de áudio e/ou registos dos ficheiros da caixa-forte, pelo que os conjuntos de dados são geralmente apenas coleções de apontadores para dados na caixa-forte. Isto permite que a Equipa de Dados honre os pedidos de eliminação dos dados de utilizadores individuais (identificados através do "ID interna") e/ou de aplicações individuais. As eliminações que têm efeito no cofre e as cópias de segurança dos ficheiros do cofre.
